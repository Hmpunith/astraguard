AstraGuard — AI Space Debris Collision Avoidance Co-Pilot
The Issue PASTE INTO: Issue and Solution → Issue
Low Earth Orbit (LEO) is dangerously congested. Over 35,000 tracked pieces of space debris now circle Earth at velocities up to 28,000 km/h — and the number grows every year. Satellite operators receive thousands of Conjunction Data Messages (CDMs) weekly alerting them to potential close approaches, but the current process for evaluating and responding to these alerts is broken: • Manual analysis is slow — engineers must assess collision probability, mission constraints, and fuel budgets under extreme time pressure with limited decision-support tools. • Decision fatigue is real — over 99% of alerts are false alarms, yet dismissing the wrong one can destroy a multi-billion-dollar asset and endanger human lives (e.g., the ISS). • No unified intelligence layer — operators juggle orbital mechanics software, spreadsheets, and experience-based intuition with no AI-powered decision support. The stakes are existential. A single high-velocity collision can generate thousands of new debris fragments, triggering a Kessler Syndrome cascade that could render entire orbital shells unusable — threatening GPS, communications, weather monitoring, and national security infrastructure that modern civilization depends on.
Our Magic Solution PASTE INTO: Issue and Solution → Our Magic Solution
AstraGuard is an AI-powered space traffic management co-pilot that acts as an intelligent air-traffic control system for Earth orbit. Built on IBM Granite, it transforms raw orbital mechanics data into clear, explainable maneuver recommendations — keeping human operators firmly in control while eliminating the cognitive burden of manual conjunction analysis. Core capabilities: 1. Real-Time Orbital Tracking — Ingests live Two-Line Element (TLE) data from CelesTrak to track satellites, rocket bodies, and debris across the catalogue. 2. Conjunction Detection — Uses validated SGP4 orbital propagation to predict close approaches within a 72-hour window across all tracked object pairs. 3. Multi-Factor Risk Scoring — Evaluates each conjunction on miss distance, relative velocity, object type, and orbital uncertainty, producing a 0–100 risk score across four severity levels: LOW → MEDIUM → HIGH → CRITICAL. 4. Maneuver Option Generation — Calculates three avoidance strategies (Conservative, Balanced, Minimal) with precise delta-V, fuel cost (via Tsiolkovsky rocket equation), resulting miss distance, and execution window for each. 5. IBM Granite AI Decision Support — Granite reasons over the computed physics alongside mission constraints (fuel budget, mission priority, minimum safe distance) to recommend the optimal maneuver with structured, explainable reasoning citing orbital mechanics principles (vis-viva equation, Hohmann transfer geometry, conjunction plane uncertainty). 6. Human-in-the-Loop Approval — Operators review the AI recommendation, examine trade-off analysis and risk factors, read a professional operator briefing, and authorize execution with a single click. Key differentiator: AstraGuard never asks AI to compute orbital mechanics — that is handled by validated SGP4 algorithms. IBM Granite operates purely as a reasoning and decision-support engine over already-computed physics results, ensuring scientific accuracy while providing the explainable intelligence that operators need to act with confidence. "Physics calculates. AI decides. Operators approve."
About the Project PASTE INTO: About
AstraGuard is a full-stack AI application developed entirely using IBM Bob for the IBM AI Builders Challenge. Tech Stack: • Backend: Python 3.11 + FastAPI, sgp4 (orbital propagation), NumPy, IBM watsonx-ai (Granite integration), httpx • Frontend: Next.js 14 (TypeScript), Tailwind CSS, Lucide React • AI Model: IBM Granite 3 8B Instruct via IBM watsonx IBM Bob was used throughout the entire development lifecycle — architecture design, code generation for all seven backend modules, React component scaffolding, API integration, debugging orbital mechanics edge cases, and writing the pytest test suite. The project is structured as a clean separation of concerns: • Orbital physics lives in validated, testable Python modules (orbit_propagator, conjunction_detector, risk_scorer, maneuver_generator) • IBM Granite handles only the reasoning layer — multi-constraint trade-off analysis, risk factor identification, and professional operator briefing generation • The React frontend provides a mission-control-style dashboard with real-time countdown timers, risk gauges, and a typewriter-effect AI briefing panel Challenge Theme: Space Exploration — AstraGuard directly addresses the challenge of making space operations safer and more intelligent through AI-powered decision support.
Questions / How IBM AI Was Used PASTE INTO: Questions
How does AstraGuard use IBM Granite AI? IBM Granite serves as the decision intelligence layer in AstraGuard's pipeline. After the Python backend computes orbital positions, detects conjunctions, scores risk, and generates three maneuver options using validated physics — Granite receives a structured prompt containing all computed results and mission constraints. It then: • Recommends the optimal maneuver from the available options • Provides 2–3 sentences of reasoning citing orbital mechanics principles (vis-viva equation constraints, conjunction geometry, Hohmann transfer theory) • Identifies the top 3 risk factors for the specific event • Performs trade-off analysis comparing all three maneuver options • Assesses secondary conjunction risks from the proposed maneuver • Generates a 4-paragraph professional operator briefing: SITUATION → RECOMMENDATION → RESOURCE IMPACT → POST-MANEUVER SCREENING The system prompt instructs Granite: "You are a certified space traffic management advisor powered by IBM Granite. Always cite orbital mechanics principles when justifying maneuver recommendations." In demo mode (no watsonx credentials required), AstraGuard generates rich mock recommendations using the same data structures, ensuring a complete and impressive demonstration. How was IBM Bob used? IBM Bob was the primary development environment for AstraGuard. Bob was used to: • Design the seven-module backend architecture (TLE fetcher, orbit propagator, conjunction detector, risk scorer, maneuver generator, Granite advisor, FastAPI app) • Generate all Python backend code including the SGP4 integration and Tsiolkovsky rocket equation maneuver calculator • Scaffold all React/TypeScript frontend components (Dashboard, ConjunctionAlert, AIAdvisorPanel, ManeuverPanel, StatsBar, MapDisplay, RiskGauge) • Build the full API client with transformer functions mapping backend snake_case to frontend camelCase • Write a 20-test pytest suite covering all four risk levels (LOW, MEDIUM, HIGH, CRITICAL) plus edge cases and invariants • Fix bugs (Pydantic v2 model_dump migration, timedelta float edge case) and improve code quality throughout What makes this a meaningful use of AI in space? The architecture deliberately constrains AI to the domain where it adds value — multi-variable reasoning and explainability — while keeping life-critical orbital physics computations in validated, deterministic algorithms. This mirrors how AI should be deployed in safety-critical systems: as a reasoning co-pilot with human override, not an autonomous black box.
